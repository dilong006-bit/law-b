## 1. 고도화 배경

- **사업팀 검토 결과:** B안 확정 후 구성·문구 검토에서 수정 9건 접수
- 기준 버전의 한계 (사업 관점)
  1. 2026년 운영 범위를 넘는 기능 노출 (진단: 법무 검수 전 참고용 규칙)
  2. 과정 수 '7개' 반복 노출: 대표 과정만 제작된 실제 공급 범위와 불일치
  3. 법정 의무·권고 구분과 법적 근거 표: 4종 세트·과태료 중심의 영업 메시지와 어긋남
  4. 계약 조건(MCP: 정·부 운영자, 월 1회 방문) 공개 노출
  5. 도입 절차가 '운영'에서 끝나 수료까지의 편의 메시지 부재
  6. 법정 문의 폼이 영업에 필요한 '교육 인원'이 아닌 '직급/직책'을 필수 수집
  7. 산업안전보건교육 수요를 받을 접점 부재
- 소스 실측으로 확인된 2차 영향: 홈 배너·플로팅 바·요약 패널의 '7개'·'진단' 잔존, 개인정보 동의문 필수 항목 불일치, 희망과정 동기화 결함 위험

> "보여줄 수 있는 것만, 약속할 수 있는 만큼만. 신청에서 수료까지 쉬운 법정교육."

## 2. 요구사항 분석

**[R15] 진단 영역 삭제 (#63)**
- 표면 요청: 필요 과정 찾기 ~ 추천 과정 모두 담기 삭제, 차년도 보완 후 재진행
- 진짜 의도: 법무 검수가 끝나지 않은 추천 규칙을 고객 앞에 내놓지 않음
- 해결 문제: 참고용 추천이 '법적 판단'으로 오인될 위험
- 성공한 모습: 진단 및 진단 의존 요소(바로가기·지표·공통 추천·문구) 0, 코드는 플래그로 보존

**[R16] 과정 수 비노출 (#64, #70)**
- 표면 요청: '7개' → '대표', 'PDF · 7개 과정' 삭제
- 진짜 의도: 공급 범위를 숫자로 고정하지 않고 '대표 과정' 포지션으로 확장 여지 확보
- 해결 문제: 과정 추가·변경 시 문구 불일치, 적어 보이는 인상
- 성공한 모습: 허브·홈 배너·소개서 카드 어디에도 과정 개수 표기 없음

**[R17] 구분·법적 근거 노출 축소 (#65, #71)**
- 표면 요청: 전체~업종별 필터 삭제, 법적 기준 섹션 이번 배포 제외
- 진짜 의도: 법정 메시지를 '4종 세트 + 과태료'로 재정리하기 전까지 분류·근거를 전면에 두지 않음
- 해결 문제: 권고·업종별 분류가 '안 들어도 되는 교육'으로 읽히는 영업 리스크
- 성공한 모습: 필터·법정 표 비표시, 후속 원고 수령 시 플래그로 재구성 가능

**[R18] 계약 조건 비노출 (#66)**
- 표면 요청: '전담 운영 지원' 카드 삭제
- 진짜 의도: 고객별 계약 조건을 표준 약속처럼 공개하지 않음
- 해결 문제: 영업 협상 여지 축소, 이행 의무 오해
- 성공한 모습: '정·부 2명', '월 1회 방문' 문구 사이트 0, 다른 점 2장으로 균형 유지

**[R19] 신청에서 수료까지 (#67)**
- 표면 요청: 4단계 문구 교체 (확정 원고)
- 진짜 의도: 담당자 부담이 '수료증 발급'까지 해결된다는 편의 약속
- 해결 문제: 기존 절차가 운영에서 끝나 결과(수료·증빙)가 안 보임
- 성공한 모습: 확정 원고 그대로, 모든 폭에서 4장 높이 균형

**[R20] 법정 문의 수집 항목 전환 (#69)**
- 표면 요청: 직급/직책 → 예상 교육 인원, 100~500 사이 중간 구간
- 진짜 의도: 견적·운영 규모 판단에 필요한 정보를 첫 문의에서 확보
- 해결 문제: 직급은 영업 판단에 쓰이지 않고, 인원 구간은 100 다음이 500이라 변별력 없음
- 성공한 모습: 법정 폼에서 예상 교육인원 필수, '~ 300명' 구간 선택 가능, 동의문과 실제 수집 항목 일치

**[R21] 산업안전보건교육 수요 접수 (#68)**
- 표면 요청: 희망과정에 산업안전보건교육 체크 추가 (자체 콘텐츠 없음)
- 진짜 의도: 콘텐츠가 없어도 수요는 받아 제휴·후속 제안으로 연결
- 해결 문제: 문의 다수 항목인데 선택지가 없어 '기타' 입력에 묻힘
- 성공한 모습: 체크 가능·유지·제출 토큰 포함, 과정 카드에는 미노출

### 3-1. LB48 진단 비표시 (Must)
- 허브에서 '필요 과정 찾기' 블록 전체 비표시 (문항, 결과 요약, 추천 그룹, '추천 과정 모두 담기')
- 코드·규칙·데이터 보존, 플래그로만 제어
- Done when: #mandatory-diagnose DOM 0, 진단 관련 GA 표식 0, 플래그 true 시 기존 화면 복원

### 3-2. LB49 헤더 바로가기·지표 정리 (Must)
- 바로가기 3 → 2 ('과정 보기', '빠른 상담')
- 지표 스트립(7 과정 · 3 문항 진단 · 4 단계 도입 · 1일 내 연락) 전체 비표시 (요청자 확정 2026-10-06), 데이터는 플래그로 보존
- 반응형: 1041 이상 바로가기 2개를 6열 폭으로 / 880 이하 전폭 2개 균등 / 560 이하 1열
- Done when: 모든 폭에서 버튼 2개 균등 폭, 지표 DOM 0, 헤더 높이 기존보다 감소

### 3-3. LB50 대표 과정 블록 정리 (Must)
- 제목: '2026 법정필수교육 대표 과정'
- 구분 필터(전체·법정 의무·권고·업종별) 삭제, '법정 의무 과정 한 번에 담기' 버튼 삭제 → 도구 줄 제거
- 카드 7장, 맞춤 구성 타일 자동 채움, 상세(인라인·바텀시트), 담기는 그대로
- 카드 구분 배지·상세 '법적 근거'는 유지 (Q5 확정)
- Done when: 제목 아래 바로 그리드, 320 폭 가로 넘침 0

### 3-4. LB51 법정 표 비표시 · 다른 점 독립 블록 (Must)
- 법정 기준(제목·표·기준일·출처·안내) 비표시, 데이터·컴포넌트 보존
- '다른 점'을 독립 블록으로 승격: kicker '차별점', 제목 'KG에듀원 법정교육이 다른 점'
- 카드 3 → 2 ('매년 새로운 시리즈', '몰입형 스토리 콘텐츠'), '전담 운영 지원' 삭제
- 그리드: 641 이상 2열 / 640 이하 1열, 높이 동일, 비교표 펼침은 카드 행 아래 전폭 유지
- Done when: '정·부 2명', '월 1회 이상 방문' 문자열 0, 641~1440 2열 높이 비 0.95~1.05

### 3-5. LB52 도입 절차 '신청부터 수료까지' (Must)
- 타이틀: '신청부터 수료까지 4단계' (Q1 확정)
- 단계 (확정 원고, 문구 수정 금지)
  1. 과정 선택 및 신청: 우리 회사에 꼭 필요한 법정교육 과정을 골라 간편하게 신청합니다.
  2. 맞춤 구성 확정: 우리 회사에 꼭 맞는 필수 과정이 맞는지 꼼꼼히 점검하고 일정·인원을 확정합니다.
  3. 교육 운영 및 독려: 전담 운영자가 학습 독려부터 진행 상황까지 밀착 관리합니다.
  4. 손쉬운 수료 완료: 번거로운 후속 절차 없이 간편하게 수료증까지 발급받습니다.
- 4단계 아이콘: 수료 의미 아이콘 신규 1종
- Done when: 1041 이상 설명 3줄 이내, 4장 높이 동일, 560 이하 세로 타임라인 연결선 정상

### 3-6. LB53 소개서 카드 메타 삭제 (Must)
- 'PDF · 7개 과정' 줄 삭제 → 제목 / 포함 칩 3 / 다운로드 버튼
- Done when: 자료 블록 짝(카드뉴스 ↔ 목차·소개서) 높이 균형 유지

### 3-7. LB54 법정 폼 인원 필드 전환 (Must)
- 법정 허브 빠른 상담 폼에 한해 직급/직책 비표시, 같은 자리(연락처 옆)에 '예상 교육인원' 선택 필드 필수 노출
- 선택지 전 폼 공통으로 '~ 300명' 추가 (~ 100명 다음, ~ 500명 앞)
- 법정 폼 선택지에서 '해당없음' 제외 (필수 항목이므로)
- 페이로드 키 불변 (jobTitle 빈 값, expectedTrainees 값)
- 개인정보 동의문: 법정 폼은 필수 항목에서 직급/직책 제외, 예상 교육인원을 필수로 표기
- 홈·/kium·기타 폼: 직급/직책 필수 그대로 (회귀 0)
- Done when: 미선택 제출 시 인원 필드 오류·포커스, 동의문 항목 = 실제 필수 항목

### 3-8. LB55 희망과정 산업안전보건교육 (Must)
- 옵션 '산업안전보건교육' 추가 (법정 과목 마지막, '기타' 앞)
- 배치: 법정 8개 2열 × 4행, '기타'는 전폭 1행 / 560 이하 1열
- 과정 카드·상세·선택 바·요약 패널·소개서에는 미노출
- 담은 과정 ↔ 희망과정 동기화가 이 옵션의 체크를 해제하지 않아야 함 (결함 위험 실측)
- Done when: 체크 → 카드 담기·빼기 → 체크 유지, 제출 토큰에 포함

### 3-9. LB56 연동 문구·요소 정리 (Must)
