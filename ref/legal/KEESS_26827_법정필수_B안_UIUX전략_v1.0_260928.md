# KEESS 26827 법정필수교육 노출 B안 UI/UX 전략 v1.0

- 업무번호: 26827 / 작성: 2026-09-28 / HRD사업지원팀 임지홍
- 전제: 노출 A안(GNB 칩 + /legal) 확인 완료. B안은 완성도 우선
- 노출 B안 정의: GNB 변경 없음 → **홈 진입점 + /content 법정 섹션 고도화**
- 조사 범위: 국내 법정교육 사이트 9곳, 글로벌 B2B 교육·컴플라이언스 15곳, NN/g·Baymard·W3C 가이드, 2025~2026 UI 트렌드 (출처는 부록)

## 0. 한 줄 전략

> "과태료로 겁주는 페이지가 아니라, 법적으로 정확하고 담당자 일을 덜어주는 페이지."

- 국내 경쟁사는 공포 소구(과태료 강조) + 긴 폼 + 부정확한 법령 표가 공통
- KEESS B안의 차별점 3가지
  1. **정확성:** 법령 검증 표 + 기준일 + 출처 (경쟁사 표 오류 다수 확인)
  2. **선택의 편의:** 필요 과정 진단 → 과정 담기 → 담은 과정 그대로 문의 (국내에 사례 없음)
  3. **전 기기 완성도:** 원 소스 반응형, 모바일 하단 선택 바, 접근성 준수 캐러셀

## 1. 레퍼런스 핵심 인사이트

### 국내 (9곳)

| 관찰 | 사례 | KEESS 대응 |
|---|---|---|
| 법령 표(교육명, 근거, 대상, 주기, 과태료)가 사실상 표준 | 휴넷, 올티칭, 드림캠퍼스 등 7곳 | 표 유지 + **의무/권고 구분, 기준일, 출처** 추가 |
| 법령 표 오류가 흔함 | 괴롭힘 예방을 의무·과태료 대상으로 표기, 퇴직연금 과태료 1,000만원 표기 등 | 법무 검증 게이트 후 게시 (§6) |

| 소개서 게이팅 | 사례 없음 | 3필드 라이트 게이트 + 문의 폼 자동 채움 |
| 운영 증빙(수료증, 이수 현황, 독려) | 전 업체 공통 | 기본 요소로 반드시 포함 |

### 글로벌 (15곳)

| 관찰 | 사례 | KEESS 대응 |
|---|---|---|
| 1차 '도입 문의' + 2차 '과정 미리보기' | EasyLlama, 360Learning | 카드마다 미리보기, 섹션 1차 CTA는 문의 |
| 폼을 본문 중간과 하단에 반복 | Traliant | 섹션 내 문의 + 페이지 하단 기존 문의 연결 |
| 카드 메타 표준(16:9, 유형 배지, 시간) | Coursera, Traliant | 16:9, [의무/권고], 차시, 대상 |
| 개별 과정 + 묶음 과정 | Traliant Topics/Tracks | 과정 7개 + '필수 5종 한 번에' 묶음 담기 |
| 캠페인은 캐러셀이 아니라 정적 카드·공지 알약 | Linear, Apple, Vercel, Docebo | 홈 히어로 공지 알약 + 정적 캠페인 카드 2장 |
| 감사 대응(audit-ready) 소구 | TalentLMS | 이수 현황·수료증·실시확인 증빙 강조 |

### 가이드라인 근거 (1순위 근거)
- 자동 넘김 캐러셀은 주목도와 조작성이 낮음 (NN/g, Baymard) → 핵심 메시지는 캐러셀 밖 HTML 텍스트로
- 5초 넘는 자동 움직임은 일시정지 수단 필수 (WCAG 2.2.2), 스와이프 대안 버튼 필수 (WCAG 2.5.7)
- 체크박스는 라벨 전체 클릭, 기본값 해제 (NN/g)
- 폼 필드 수와 전환은 반비례 (방향성 참고, 2차 인용 수치)

## 2. 정보 구조 (노출 B안)

### 사이트 수준

| 위치 | 요소 | 역할 |
|---|---|---|
| GNB | 변경 없음 | 4필러 구조 유지 |
| 홈 히어로 | **공지 알약** '2026 법정필수교육 · 과정 보기 →' | 첫 화면 진입점 (6장 슬라이드 공통 고정) |
| 홈 히어로 바로 아래 | **캠페인 밴드** 정적 카드 2장 (법정필수 / 인재키움 공개교육) | 시즌 캠페인 영역 |
| /content 히어로 | 6축 맵의 '법정 헌터스' 타일에 '2026' 배지 | 페이지 내 진입 |
| /content #mandatory | **법정필수교육 허브**로 확장 | 탐색·검증·전환 |

- 히어로 캐러셀에 슬라이드를 추가하지 않는 이유: 두 번째 이후 슬라이드 노출은 급감 (Baymard)
- 공지 알약은 모든 슬라이드 위에 고정 → 첫 화면에서 반드시 보임
- 캠페인 밴드의 인재키움 카드는 9/21 합의(메인 공개교육 노출) 수용 자리. 26827은 밴드 구조 + 법정 카드 담당, 인재키움 카드 내용은 해당 태스크에서 확정

## 3. 핵심 인터랙션 설계

### 3-1. 과정 담기 흐름 (B안의 중심)

```
진단(선택) → 추천 과정 자동 담기 → 카드에서 담기/빼기 → 선택 바 "선택 과정 N개 · 문의하기" → 문의 폼 희망과정 자동 체크
```

- 담기 상태는 한 곳(상태 저장소)에서 관리: 진단, 카드, 묶음 담기, 폼 체크박스가 모두 같은 값
- **선택 바**
  - PC·태블릿: 허브 영역 안에서 하단에 붙는 바 (허브를 벗어나면 숨김)
  - 모바일: 화면 하단 고정 바, safe-area 반영, 44px 이상
  - 선택 0개면 숨김. 개수 변화는 숫자만 부드럽게 전환 (240ms)
- 폼에서 체크를 바꾸면 카드 담기 상태도 함께 바뀜 (양방향)
- 과정 선택 없이도 문의 가능 (진단·담기는 도움 기능이지 필수 단계가 아님)

### 3-2. 필요 과정 진단 (3문항)

| 문항 | 선택지 | 반영 규칙 (초안, 법무 검수 필요) |
|---|---|---|
| 상시 근로자 수 | 10인 미만 / 10~49인 / 50인 이상 | 전 구간: 성희롱 예방, 장애인 인식개선 |
| 퇴직연금(DB·DC) 도입 | 예 / 아니오 / 모름 | 예·모름: 퇴직연금 가입자 교육 |
| 업종 | 금융 / 공공 / 일반 | 금융: 자금세탁방지 / 공공: 윤리경영 / 공통 추천: 개인정보보호, 직장 내 괴롭힘 예방(권고) |

- 결과 화면: 의무 / 권고 / 업종별로 묶어 표시 + '추천 과정 모두 담기'
- 안내 문구 필수: '참고용 결과입니다. 정확한 대상은 상담 시 확인해 드립니다.'
- 문항은 한 화면에 칩 선택으로 (페이지 이동 없음), 모바일에서는 문항별 세로 배치

### 3-3. 과정 상세 패널
- 카드 본문 클릭 → 상세 패널 (PC: 우측 드로어, 모바일: 바텀시트)
- 재사용: /kium 과정 패널(KiumCoursePanel) 구조
- 내용: 썸네일, 과정명, 학습 대상, 학습 목표, 주요 학습 내용, 차시, 강사(SME) 이름·약력 1줄, 근거 법령
  - 출처: 2026 법정필수교육 소개자료 PDF p.9~15 (**교육비 제외**, p.9 학습 내용 오기재 수정본 사용)
- 하단 버튼: [담기] (1차) / [맛보기 보기 ↗] (새 탭)
- 이점: 새 탭 이동 전에 사이트 안에서 과정 정보를 먼저 확인 → 이탈 감소

### 3-4. 카드뉴스 (재제작본 기준)
- 매수: 허브 자료 영역은 재제작본 전체, 홈 캠페인 카드는 3~5장 요약본 권장 (NN/g 5장 이하)
- 홈 카드: 카드 제목·설명·CTA는 **캐러셀 밖 HTML**. 카드뉴스는 보조 시각 요소
- 규칙
  - PC: 6초 자동 넘김, 재생/정지 버튼 상시 노출, 마우스·포커스 시 정지, 사용자 조작 후 자동 넘김 중지
  - 모바일·움직임 줄이기: 자동 넘김 끔, 스와이프 + 이전/다음 버튼
  - 위치 표시 '2 / 5' 숫자 병기
  - 이미지 속 문구는 대체 텍스트로 전문 제공 (카드뉴스는 글자가 이미지에 들어가므로)
- 디자인 파트 재제작 요청 규격: 1080×1350(4:5), KG CI 가이드 준수, 톤앤매너 존댓말, 과태료 수치 미표기(법무 검증 전)

### 3-5. 법정 문의 폼
- 기존 문의 폼 구조와 제출 데이터는 유지 (운영 이관 용이)
- 화면 구성만 조정
  - 필수: 회사·기관명, 담당자명, 연락처, 이메일, 희망과정
  - '추가 정보 (선택)' 접기: 직급, 회사규모, 예상 교육인원, 문의 내용, 첨부
  - 확인 필요: 운영 폼에서 필수인 직급/직책을 선택으로 낮춰도 되는지 (요청자·운영 확인)
- 소개서를 먼저 받은 사용자는 회사·이름·이메일 자동 채움 (같은 세션 안)
- 희망과정: 담은 과정 칩으로 표시 + 체크박스 수정 가능

## 4. 비주얼·폴리시 원칙

### 기준
- Design.md 토큰·컴포넌트만 사용. 신규 패턴 3종(진단, 선택 바, 상세 패널)은 기존 컴포넌트 조합으로 구성하고 Design.md 부록으로 등록
  - 진단: 칩(pill) + 카드
  - 선택 바: 기존 버튼 + 스낵바(TeaserSnackbar) 위치 규칙
  - 상세 패널: /kium 과정 패널

### 톤
- 다크는 홈 히어로·/content 히어로에만. 허브 본문은 P4 틴트 라이트 캔버스
- P4 오렌지는 배지·선택 상태·CTA 강조에만
- 풀채도 블록은 페이지당 1개 규칙 유지 (법정 문의 좌측 패널)

### 폴리시 5축 (트렌드 스킬 기준 + 사이트 토큰으로 치환)

| 축 | 적용 |
|---|---|
| 모션 | 등장 .7s 기존 리빌, 인터랙션 .2~.35s `var(--ease)`. 담기 체크는 아이콘 전환 + 카운트 숫자 전환만. 바운스 금지 |
| 깊이 | 기존 shadow-1~3만. 카드 기본 1, hover 2, 패널·바텀시트 3 |
| 디테일 | 구분선 `var(--line)` 1px, 카드 20px 라운드 안의 썸네일은 라운드 동심 맞춤, 칩 pill |
| 타이포 | 차시·과태료·인원 숫자는 tabular-nums, 섹션 제목 자간 기존 값, 한글 keep-all |
| 상태 | 썸네일 로딩 자리(비율 고정 회색 면), 진단 결과 전환, 선택 0개 안내 문구, 제출 성공 화면(기존 RD-011) |

### 글래스 사용 범위
- 홈 히어로 공지 알약에만 (기존 `btn-glass` 재사용). 허브 본문에는 사용하지 않음 (가독성·성능)
